# 5b · Domains 3: Deep Research Agents：课程笔记

课件：[lecture-10-deep-research-agents.pdf](lecture-10-deep-research-agents.pdf)。下文采用本地 PDF 的实际页序，连续的演示页合并讲解。数字来自课件，额外推导和解释标为“补充理解”。

## 从查一个事实到形成可核查的结论（第 1–12 页）

Akari Asai 用两个问题区分任务类型。查教师办公室会先找到 CMU LTI 官方简介，再提取该属性。课件示例保留了页面截图日期，所以答案对应当时的页面。另一个问题是“AI Agent 能否像人类专家一样综合科学文献”，它需要先确定“像专家一样”如何比较，再找多种证据。

1. **计划**：找文献综合研究，检查比较对象、任务和领域。
2. **搜索**：找到 OpenScholar 的专家评估，也找到 DR Tulu 的长报告基准结果。
3. **反思并搜索下一轮**：确认两种实验用了哪些任务、如何评分，是否真的有人类专家作对照。
4. **综合**：课件把结论限定在已评估的任务。OpenScholar 提供部分回答的人类专家直接比较，DR Tulu 提供多个长报告基准上的系统比较。进一步推广到其他领域需要证据。

深度研究的基本单位是随证据变化的**信息需求**。例如第一轮发现论文后，第二轮要问评估协议和覆盖范围。最后的回答需要把主张绑定到对应来源，让读者能回查。

~~~mermaid
flowchart LR
    Q[研究问题] --> P[分解问题并选择下一项信息需求]
    P --> S[搜索并阅读来源]
    S --> E[核对证据支持的主张与适用范围]
    E -->|仍有证据缺口| P
    E -->|可回答| A[综合结论并附引文]
~~~

## 为什么单一 QA 准确率不够（第 13–20 页）

Natural Questions 的例子问谁为《原力觉醒》配乐，参考答案是 John Williams。匹配一个短答案能测事实问答，但课件提出深度研究要分别观察四个维度：

| 维度 | 要验证的问题 | 课件代表基准 |
| --- | --- | --- |
| 搜索复杂度 | 能否组合多个难找的线索 | BrowseComp、BrowseComp-Plus |
| 领域专业性 | 能否识别并使用专业来源、理解领域口径 | MedBrowseComp、FinSearchComp |
| 回答质量 | 长文是否准确、覆盖充分，且保留结论限定语 | ScholarQABench、ResearchQA |
| 证据支持 | 引用页面是否支持报告中的相应主张 | DeepResearch Bench 的 FACT |

补充理解：短答案正确可能来自记忆或一次查询。若要测试综合证据能力，可以单独检查找到了什么、如何串联，以及最终结论是否保留来源条件。

## 难搜索与专业检索怎样出题（第 21–34 页）

**BrowseComp** 有 1,266 道人工问题。从已知人物、事件或作品出发，隐藏名称，用多个事实线索构题。模型与搜索检查用于排除容易查到的题，课件提到“五次 Google 搜索不足以解决”以及在部分题上检查人类十分钟内是否仍感困难。示例同时给出行为、背景、性格和剧集年份及数量线索，参考答案是 Plastic Man。找到候选后仍需逐条交叉核对。

| 第 25 页报告的系统 | 参考答案匹配率 |
| --- | ---: |
| GPT-4o | 0.6% |
| GPT-4o + 浏览工具 | 1.9% |
| GPT-4.5 | 0.9% |
| OpenAI o1（medium） | 9.9% |
| 为 BrowseComp 类任务训练的 Deep Research | 51.5% |
| 人类参考答案匹配 | 25.3% |

人类尝试了 1,266 题中的 1,255 题。表格对应这个基准与设置。第 26 页还显示 Tongyi DeepResearch 在课件对照中随上下文从 8K 扩至 128K 而提高准确率。评估每题最多 128 次工具调用，SFT 数据中超过 20% 的轨迹使用 10 次以上工具调用。上下文长度和调用上限是不同预算，前者影响多少往返历史可留在输入中。

**BrowseComp-Plus** 将语料固定。先由 o3 找候选证据，人工检查每条线索、标记支持片段和答案文档，再加入主题相关但缺少关键线索的困难负例。最终有 830 道题和 100,195 份文档。固定语料便于在同一文档集合上比较不同检索和搜索策略。

**专业基准**要求检索后还懂得如何使用证据。FinSearchComp 从真实工作情境或已核验表格出题，专家检索可靠数据、计算并交叉复核。课件例子问强生 2022–2024 年国际收入占比逐年变化，涉及会计口径和比例计算。MedBrowseComp 需要连接试验、药物与监管事实。ScholarSearch 和 AutoResearchBench 则测试学术搜索，目标可能是一篇论文，也可能是找齐符合条件的论文。

## 开放报告怎样评分：相似度、量表与引文（第 35–50 页）

**相似度的局限**：一句“在测试任务上获得专家偏好，跨领域仍未证实”可有多种正确表达，而把“未证实”改成“已证实”只改了几个字，却反转了结论。第 38 页在 109 组专家比较中用相似度选择专家偏好的回答，ROUGE、BERTScore、BLEURT 的选择准确率分别为 58%、57%、62%，随机基线是 50%。

**Rubric（分项量表）**将质量拆成可判定的条目。ScholarQABench 示例给“报告与专家直接比较”权重 2，给“限定适用任务与领域”权重 1。候选答到直接比较却声称适用所有领域，得到 $(2\times1+1\times0)/(2+1)=0.67$。第 42 页在 12 个问题、2 个系统、每个回答 2 位专家的设置中，专家与模型的量表判断一致率为 79%，专家之间为 80%。

**量表也要审。** ResearchQA 从综述中生成问题和量表，课件统计约 21K 问题、75 个领域、160K 条目。专家审计发现，依赖模型参数知识生成的条目中约 15% 空泛、有错或含糊。例如引用不存在的论文、重述问题，或写成无法判定的要求。DeepResearch Bench II 使用专家报告派生条目，并做人工修订与专家评审。

**FACT 引文检查**：提取主张与引用 URL，阅读对应页面，再判定该页面能否支持主张。课件让两条主张引用同一 OpenScholar 论文。“做过专家直接比较”有依据，“在所有领域达到专家水平”缺乏依据。于是 2 个主张与引文配对中只有 1 个支持，引文准确率为 50%，有效引文计数为 1。补充理解：还可以检查关键主张有没有引文，因为只核查已经带引用的位置会漏掉未引用的断言。

## 推理循环与训练数据从哪里来（第 51–73 页）

推理时，模型生成搜索意图和工具调用，工具执行查询并把结果加入上下文。模型继续读证据，决定补查、调整查询还是回答。课件用不同颜色标出模型生成部分与外部输入：搜索语句、回答等由模型产生，用户问题与工具结果作为条件上下文。这个边界对应 4b 的监督掩码。

| 阶段 | 典型数据与作用 |
| --- | --- |
| 中期训练 | 把 Agent 轨迹混入通用预训练数据，继续做 next-token prediction，让基座适应交互 |
| SFT | 收集教师轨迹，留下答案正确、格式有效、过程连贯的示范 |
| RL | 用当前策略生成带搜索的尝试，按答案或报告质量评分再更新 |

**用知识图谱合成可验证问题。** 从有出处的事实建图，实体作节点，带标签的关系作边。抽连通子图，隐藏目标实体名，用关系构造问题。课件用 Allen Newell 与 Herbert Simon 合著《Human Problem Solving》、共享 1975 年图灵奖，以及 Simon 获 1978 年经济学奖等事实生成多线索题，已知答案为 Allen Newell。补充理解：合成后可核查题目是否泄漏答案、线索是否仍受来源支持、是否出现另一个也满足全部条件的候选。

**SFT 过滤**要同时看答案与执行。答对但工具调用格式无效的轨迹会教错接口，格式可解析但答错的轨迹会教错误完成路径。课件的中期训练对照固定下游 SFT-B 数据，只改变初始化：

| 基准 pass@1 | Qwen3 基座 + SFT | AgentFounder 基座 + SFT |
| --- | ---: | ---: |
| BrowseComp-en | 28.6% | 39.9% |
| BrowseComp-zh | 35.6% | 43.3% |
| GAIA | 71.8% | 72.8% |

该组结果中，BrowseComp 的提升大于 GAIA，说明读训练收益需要保留任务差异。

## 短答案强化学习与异步轨迹（第 74–83 页）

**RLVR（可验证奖励强化学习）**可用已知答案给搜索轨迹评分。课堂示例对三条尝试的最终答案 Herbert Simon、Allen Newell、Allen Newell 做精确匹配，奖励为 [0, 1, 1]。同一题的 GRPO 更新相对鼓励高于组均值的轨迹。第 79 页在 5a 的简化优势加权上加入三项：

- **概率比 ρ**：比较当前策略和采样策略给生成 token 的概率。
- **裁剪**：限制目标对某些方向上过大的概率变化所给的额外收益。
- **KL 项**：惩罚策略偏离参考模型。

**异步 rollout** 允许多条轨迹各自完成模型生成和工具交互。任务的调用次数和工具等待时间不同，完成后分别评分，再组装用于更新的批次。缓存、稳健的 API 处理和后台任务准备可以减少等待。Tongyi 的训练图显示奖励随步数上升、策略熵相对稳定。课件把它作为 RL 训练曲线，图中没有隔离各训练阶段的收益。

## DR Tulu：把开放报告的质量变成训练信号（第 84–98 页）

开放报告有多种可接受写法，奖励需要衡量覆盖、相关性、事实性和证据支持。DR Tulu 用 **RLER（Reinforcement Learning with Evolving Rubrics）**让量表与策略一起更新。

1. 从研究问题与搜索证据产生初始条目，保留在量表缓冲区。
2. 当前策略为同题生成多个报告，收集新的搜索证据和回答之间的分歧。
3. 对比候选报告，生成可区分它们的条目，例如核查新增事实，或检测反复出现的错误主张。
4. 结合已有与新增条目打分。课件简化式为 $r_i=\sum_k w_k\,\mathrm{Judge}(c_k,y_i)/\sum_k w_k$，辅助奖励省略。
5. 用评分更新策略，训练过程中继续积累并复用条目。

第 93 页的医学研究图用于说明方法：不同报告对细胞因子与信号通路给出不同解释，研究证据可变成具体条目，分别奖励有支持的发现和识别错误说法。这里记录的是评估机制。

- **成本与表现（第 94 页）**：纵轴是四项长报告研究基准的平均表现，横轴是 ScholarQA-CSv2 的每查询推理成本，使用对数尺度。DR Tulu-8B 位于课件比较中的较低成本、高表现区域。
- **SFT 热启动（第 95 页）**：少量 SFT 已改善起点，完整 SFT 混合在图中得到最强后续结果。灰色区间横轴步数间距不均，需要按标注读取。
- **演化量表对照（第 96–98 页）**：与无 RL、随机奖励、仅初始量表相比，演化量表在所示训练后段最高。纵轴是 HealthBench、ScholarQABench v2 和 DeepResearch Bench 的平均成绩，固定初始量表也较随机奖励取得更明显的收益。

## 从 BM25 到为研究步骤检索（第 99–111 页）

| 工具 | 适用场景 |
| --- | --- |
| BM25 等词法检索 | 查询含有准确标题、编号、术语或独特短语 |
| 向量检索 | 相关证据与查询表达不同，仍需按语义召回 |
| Web 搜索 API 与浏览 | 广泛发现在线来源，再打开网页读取上下文和出处 |
| 学术搜索与代码执行 | 在领域索引中找论文，或计算、整理已查到的数据 |

**双编码器**离线用文档编码器 $E_d$ 建向量索引，在线将查询交给查询编码器 $E_q$，以点积 $s(q,d)=E_q(q)^\top E_d(d)$ 排序，返回 top-k。对比训练提高正例相对负例的分数，即让 $\exp s(q,d^+)$ 在正负样本的 softmax 分母中占更大比重。“谁与 Simon 分享图灵奖”的正例应提到 Newell 和 Simon 共同获奖，只提到 Simon 的另一奖项不足以回答。

**AgentIR** 让检索器同时接收当前查询与当前推理，训练目标是为这一轮找到有用文档。普通检索常只见最后一句查询。补充理解：同一句“专家对比”可能要找人类偏好结果、评估协议或所覆盖的学科。当前研究步骤可以帮助检索器区分这些意图。

**DR-Synth** 为中间搜索构建监督。先取当前查询的候选结果，再加入全局已知的证据文档。第 111 页的图使用全局问题与已知答案引导重排，根据重排前部和尾部生成正负标签。这里的答案参与离线标注。实际运行时，检索器由查询与当前推理判断相关性。中间检索标签把“能帮助回答总问题的证据”落实到每次搜索的候选集合中。

## AgentIR 消融：当前推理比堆叠整段历史更有效（第 112–124 页）

第 114 页以搜索调用次数为横轴、准确率为纵轴。所示三个 Agent 搭配 AgentIR-4B 时，相对 BM25 和 Qwen3-Embed-8B 位于更高准确率、较少搜索调用的区域。调用次数与总耗时是不同指标，图中比较的是调用数。

| 第 118 页准确率 | 仅查询 | 加当前推理 | 加 DR-Synth 训练 | 两者都用 |
| --- | ---: | ---: | ---: | ---: |
| Tongyi-DR | 48.7% | 55.5% | 59.4% | 66.3% |
| gpt-oss-120B | 47.6% | 51.3% | 59.2% | 67.0% |
| GLM-4.7 | 50.5% | 50.9% | 57.5% | 64.7% |
| Tongyi-DR（visit） | 50.2% | 54.0% | 59.5% | 68.1% |

单独加推理、单独换训练数据都有收益，结合后在四个配置中最高。第 123 页固定 DR-Synth 训练，只比较输入。以 Tongyi-DR 为例，仅查询为 59.4%，加入先前查询为 63.1%，再加历史推理仍为 63.1%，连历史文档一起加入为 60.0%，使用当前推理为 66.3%。课件所示配置均以当前推理得分最高。补充理解：历史里可能同时包含已解决和已排除的方向，检索时应先确定本轮还缺什么。

## 复习：从任务目标反推证据、评估和训练

| 想改进的环节 | 先问什么 |
| --- | --- |
| 搜索 | 当前子问题缺哪条证据，查询里有没有写清年份、实体和比较对象？ |
| 综合 | 各研究用了同一种比较吗，结论能推广到哪些任务？ |
| 评估 | 参考答案、分项量表与引文检查分别覆盖哪些要求？ |
| 训练 | 能否用短答案精确校验？报告任务的量表是否经证据和人工检查？ |
| 检索 | 是召回缺失，还是检索器只看到短查询、缺少当前信息需求？ |

用开头的文献综合问题复述一遍：先区分基准得分与直接专家比较，再选择相应论文、审查实验对象与适用范围，最后逐条核对引文能否支撑报告里的具体说法。
