# 10a · Agents and the Future of Work

课件：[2026-10-27-zora-wang.pdf](2026-10-27-zora-wang.pdf)。下文使用实际 PDF 页序。数字是课件所引研究的口径，补充解释单独标明。

## 能把软件任务做长，离真实工作还有多远（第 1–15 页）

这节课从三类证据出发：受控基准、真实工作交付物、工作中的实际采用。METR 曲线的纵轴是**人类完成任务所需的时间**，按模型能以 50% 概率完成的任务长度作比较。课件用“约每七个月翻倍”描述其趋势，图上也标明超过 16 小时的测量区间可靠性较低。**补充理解**：这是特定软件任务上的成功时域，不表示 Agent 每七个月能自动化两倍岗位，也不能用 50% 的完成率代表生产验收标准。

真实工作还要求可用的交付物与适配现有流程。Remote Labor Index 展示科学文档排版和建筑设计等项目，具有原始文件、详细规格与成品要求。课件指出开发活动集中在计算机和数学领域，所引研究中这些职业约占 5% 就业。同时，理论上可覆盖的任务和人们实际使用 AI 完成的任务存在差距。

**自主表现与协作品质需要分别量化。** 第 9 页示例里，三个工具的自主排行和 CollabSkill 排行顺序不同：前者是 Gemini CLI、Codex、Claude Code，后者是 Claude Code、Codex、Gemini CLI。图示反映该研究设置。协作评估还要观察能否询问关键问题、响应反馈、交付人类需要的形式。

## 怎样选出能代表工作的任务（第 16–25 页）

课件把工作基准拆成任务、环境和评估三个部分。任务规定要做什么，环境提供软件和数据，评估说明交付物何时可用。用同样的任务描述，若缺了真实需要的数据或验收只看文件存在，得分就很难支持关于岗位工作的结论。

| 任务采集方式 | 课件实例 | 覆盖与限制 |
| --- | --- | --- |
| 由职业专家写任务 | GDPval，课件列出 44 类岗位、9 个主要行业及 220 项任务，专家平均 14 年经验 | 可提供行业约束和验收准则。采到的任务只覆盖职业库的一部分 |
| 从自由职业项目采集 | Remote Labor Index，358 位自由职业者、240 个项目、覆盖 Upwork 23/64 个类别 | 涵盖在线外包的长尾工作与成品形式 |
| 按人们愿意委派的程度取样 | JobBench | 让“能自动化什么”和“人希望交给 Agent 什么”都进入任务选择 |
| 采集真实 GUI 历史 | OpenCUA，课件约 22.5K 条轨迹，覆盖 Windows、macOS、Ubuntu | 可观察实际操作，个人数据和高层意图需要额外处理 |
| Agent 探索生成任务 | Bagel、NNetNav | 可扩充训练任务，任务代表性仍需验证 |

**构念效度（construct validity）**问的是分数对目标现象能支持多强的结论。若声称系统擅长协作，任务需要允许人介入，评分要覆盖沟通和修订。如果基准只要求独立完成 Python 补丁，即使它有稳定分数，也主要支持对该类软件任务的判断。课件引用的调研图还检查了构念定义、抽样来源、任务复用及统计检验，提醒读者区分方便衡量的量与目标能力。

## 环境如何构造，以及为什么环境也影响难度（第 26–33 页）

TheAgentCompany 使用自托管开源软件来重现工作环境。课件例子把 GitHub 的数据迁入自建 GitLab，使界面可交互，也保留仓库内容和工作背景。Gym-Anything 以职业覆盖与经济活动为参考选软件，再由编码 Agent 准备可运行环境和数据。Terminal-Bench 则将依赖和任务文件组织在目录里，适合文件与命令行操作。

| 设计选择 | 要复核的点 |
| --- | --- |
| 抓取已有数据 | 实际记录更贴近工作，但需处理授权、私密材料和应用格式差异 |
| 合成数据 | 可控制初始状态、重复运行。要检查分布、干扰项和专业字段是否合理 |
| 使用文件或开源替代软件 | 便于打包和复现。若现实中的专有软件、权限或多人协作是核心，应说明替代环境仍覆盖哪些条件 |

**补充理解**：多放文件不会自然产生长任务。课件强调真实性、多样性和难度，可以用确实会影响交付的相关信息与干扰信息来检验查找和判断。

## 从测试通过到开放交付：不同证据怎样组合（第 34–45 页）

| 验收方法 | 能检查什么 | 课件指出的限制 |
| --- | --- | --- |
| 执行测试 | 代码补丁能否运行，预期输出与回归是否符合 | 覆盖限于定义好的检查 |
| 人类专家量表 | 把开放交付拆成内容、准确性、可用性等要求 | 设计和人工核查成本较高 |
| LLM 裁判与量表 | 在较大规模上判各项是否满足 | 有输出变动、自偏好和视觉判断不足等问题 |
| 演化量表 | 对比 rollout 后增加更有区分度的要求，用于训练 | 要核实新增条目有证据，并控制对特定模型或用户的过拟合 |

课件把 GitHub issue 修复、数据清洗分析和室内设计放到从可验证到开放的谱系上。一个报告可以用程序核算数值，再用量表判断解释是否支持决策。第 38–43 页依次介绍人类专家写量表、LLM 派生量表并人工核查、DR Tulu 在训练中演化量表，以及用用户反馈生成可评分规则。量表设计和裁判可靠性是两项独立工作。

第 42 页同时展示裁判准确性与自偏好指标。即使平均准确性较高，个别配置仍会偏向自己所属模型的输出。第 44–45 页补充静态基准的污染和饱和问题，LiveCodeBench 作为以时间更新任务的例子。**补充理解**：若更换题集或裁判，应保留版本、切分和评分办法，否则很难判断变化来自模型还是测量方式。

## 能力之外，协作方式与效率也决定能否采用（第 46–53 页）

第 47 页的 HAS H1–H5 是人机分工谱系。H1–H2 由 Agent 主导，程度从无需参与到在关键点需要输入。H3 是合作伙伴共同完成。H4–H5 由人主导，Agent 的帮助程度逐步降低。CowPilot 代表执行时可接手和引导的界面。后续研究还尝试让 Agent 判断用户是否在介入以及自身应采用的自治程度。

| 课件关切 | 为什么应与完成率同时看 |
| --- | --- |
| 效率 | 多 Agent 或多次反复在复杂任务中可能重复搜集和验证，同样的完成率可能消耗不同时间与资源 |
| 隐私、安全和错误恢复 | 真实工具执行可能改变外部状态，意外风险可在正常用户请求下出现。课件用 OpenAgentSafety 等工作说明需要实际交互中的发现机制 |
| 工作体验 | 有些工作片段虽然可自动化，仍可能是人愿意保留的创作、判断和学习过程 |

## 职业由任务组成，受影响与被替代需要分别理解（第 54–62 页）

第 55 页引述的暴露估计称，美国约 80% 的劳动者至少 10% 的任务可能受影响，写作和编程是课件列出的例子。这是**任务暴露**估计。第 57 页则报告受调查者在约 46% 的职业任务上表示希望自动化。图的两个轴分别是人的自动化意愿与专家所估计的自动化能力，因此可同时识别“意愿高、能力有限”的研发机会，以及“能力高、意愿低”的情形。

课件引用任务置换与新增任务的分析，讨论技术如何改变工作分工。初级员工就业图按 AI 暴露程度比较 22–25 岁组，展示该研究历史数据中的组间走势。**补充理解**：组间趋势可以提示需要研究入门岗位和学徒式机会，图本身不足以把全部变化归因于 AI。课程最后还指出，基础工作常同时训练判断力。若把它交给 Agent，交付效率和培养新人的路径都值得单独衡量。

## 把研究结果映射到可比较的指标（第 3、7、11–12、42、47、55–60 页）

| 课件观察 | 指标的单位 | 读数边界 |
| --- | --- | --- |
| METR 软件任务曲线 | 人类完成所需时间，模型成功率门槛为 50% | 依赖基准任务和人类参考时长。若上线要求较高成功率，需要使用相应门槛重估 |
| Remote Labor Index | 独立项目与成品 | 项目可能跨工具，读分数时应核对附件、专业规格与可打开的交付物 |
| 工作中的实际使用 | 某类任务的使用覆盖 | 使用受企业流程、接入、授权和人们是否愿意委派影响 |
| 人机协作 | 各自承担的工作、主动人力、产出质量 | 等长的模型运行时间可能对应很不同的人工投入 |
| 任务暴露及自动化意愿 | 工作任务占比或调查回答 | 同一岗位内各任务可受不同影响 |
| 早期就业趋势 | 某年龄段在不同暴露组的就业走势 | 因果结论需要在暴露分组之外控制其他影响 |

**补充理解**：用技术案例读 HAS 谱系。处理已知格式的文件更接近 H1–H2，Agent 可先工作并在歧义处请人决定。探索式分析可能接近 H3，人和 Agent 反复核对假设。若任务涉及方向选择和最终判断，H4–H5 可让人承担主要工作，Agent 做信息补充。一次任务也可能在不同阶段切换模式，因此评价时要记录介入发生在哪一步。

## 复习：用同一个任务检查三层问题

以整理一份需要查多份收据的报表为例。先问任务的来源是否能代表现实工作，再检查软件、权限和数据是否具备所需条件，最后分开验收计算正确性、交付可用性和人机协作质量。如果模型分数提高，还可以核对用户主动工时、运行开销以及哪些部分仍需要人做决定。
